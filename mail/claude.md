# AGENT.md — Private Business Mail Platform

## Project Overview

We are building a **private business email infrastructure**, similar in concept to Zoho Mail or Google Workspace Mail, but **NOT public**.

The system is intended only for:

* Internal company usage
* Managed customer domains
* SaaS integration (Bizly platform)

Public registrations are NOT allowed.

This is a **Mail Platform as a Service (MPaaS)** integrated into our SaaS ecosystem.

---

## Core Philosophy

We DO NOT build a mail server from scratch.

Mail protocols (SMTP, IMAP, DKIM, spam filtering, queues) are handled by an existing mail stack.

Our development focuses on:

* orchestration
* automation
* provisioning
* administration layer
* API integration
* SaaS automation

---

## Mail Engine

Mail infrastructure is powered by:

* Mailcow Dockerized
* Postfix (SMTP)
* Dovecot (IMAP)
* Rspamd (Anti-Spam)
* SOGo (Webmail)
* ACME / Let's Encrypt

The mail engine is treated as an **external infrastructure service**.

Developers MUST NOT modify internal mail services.

All operations happen through the Mailcow API.

---

## System Architecture

```
Bizly SaaS Platform
        ↓
Mail Management API (our backend)
        ↓
Mailcow REST API
        ↓
Mail Infrastructure
```

## Entities

### Company

Represents a customer organization.

Fields:

* id
* name
* owner_id
* plan
* status

---

### Mail Domain

Represents a domain attached to a company.

Fields:

* id
* company_id
* domain
* verified
* dkim_status
* spf_status
* dmarc_status

---

### Mailbox

Represents an email account.

Fields:

* id
* domain_id
* email
* password_hash
* quota
* active

---

## Required Backend Responsibilities

The backend MUST:

* Create domains via Mailcow API
* Create mailboxes
* Reset mailbox passwords
* Suspend mailboxes
* Delete mailboxes
* Manage quotas
* Store metadata locally
* Sync with Mailcow state

The backend MUST NOT:

* Implement SMTP
* Implement IMAP
* Handle email delivery logic
* Replace Mailcow services

---

## Provisioning Flow

When a company is created:

1. Create Company record
2. Attach mail domain
3. Generate DNS configuration
4. Verify domain ownership
5. Create default mailboxes
6. Send credentials

Everything must be automated.

---

## DNS Requirements (Generated by System)

The platform must generate DNS instructions:

* MX record
* SPF record
* DKIM record
* DMARC record
* Autodiscover record

Users should only copy/paste.

---

## Security Rules

* TLS enforced everywhere
* SMTP authentication mandatory
* Rate limiting per mailbox
* No anonymous relay
* Password hashing required
* API authentication required

---

## API Design Principles

* API-first
* Stateless services
* Clear separation between infrastructure and business logic
* Mailcow treated as provider dependency

---

## Future Expansion
